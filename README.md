# Часть 2. Архитектура базы данных

Для хранения прогресса пользователя я бы использовал три таблицы:

1. **lessons** — список уроков. Хранит сами уроки и их порядок.
2. **users** — данные пользователей. В Supabase создаются через встроенный Auth.
3. **user_lessons** — прогресс пользователя. Связывает пользователя с конкретным уроком и хранит статус прохождения:
    - `locked` — закрыт
    - `active` — открыт
    - `done` — завершён  
      Также хранится дата начала и завершения. Пара `user_id + lesson_id` уникальна, чтобы не было дублей.

**Связи:**
- `user_id` → `users.id`
- `lesson_id` → `lessons.id`  
  Каждый пользователь может иметь много записей прогресса — по одной на каждый урок.

**Логика для фронтенда:**
- Один запрос возвращает все уроки сразу с их статусом для конкретного пользователя.
- Если записи о прогрессе нет:
    - первый урок считается `active`,
    - остальные — `locked`.
- Если предыдущий урок завершён (`done`), следующий автоматически становится `active`.

 фронту приходит готовый список уроков, где сразу понятно, что открыто, а что закрыто.
